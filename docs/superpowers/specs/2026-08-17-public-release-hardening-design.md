# VMQFox 2026 公开发布加固设计

## 目标

在保持旧版支付接口、现有 APK/KSU 通信格式和二维码管理功能可用的前提下，完成公开仓库发布前的路由、认证、监控重放、管理员初始化、示例页面和容器依赖加固。

## 已确认的约束

- 公开 REST 路由与需认证 REST 路由继续采用方案 A 分组。
- KSU 模块使用现有协议：心跳和收款推送的 `t` 可能是 10 位秒或 13 位毫秒时间戳。
- 旧版 `/appHeart`、`/appPush`、`/createOrder`、`/getOrder`、`/checkOrder` 等接口继续兼容。
- 不要求现有部署执行额外数据库迁移；重放记录使用现有 `setting` 表的内部键，并从配置响应中隐藏。
- 公开发行版不再分发审计不充分的旧 `public/v.apk`；文档保留与 KSU 模块的互斥说明。

## 方案

### 1. 路由与认证边界

新增 `config/route.php`，设置 `url_route_must=true`，让未声明的自动控制器路径返回 404。删除 `admin/index/:action` 通配路由，保留前端实际使用的显式兼容路由，并把后台控制器中的 `getCurl()` 改为私有方法。这样路由中间件不会被自动路由或不同 HTTP 方法绕过。

公共接口只保留登录、订单创建/查询、支付返回地址和监控签名入口；用户、配置、订单管理、二维码管理和后台设置继续挂载 `CORS + Auth`。

### 2. 支付返回地址

`generateReturnUrl()` 只允许订单状态为已支付的状态生成带签名 URL（状态 `1` 或通知失败但已完成支付的状态 `2`）。未支付、已关闭和不存在的订单统一返回错误，不泄露可被当作支付成功的签名。

### 3. 监控请求时效与重放保护

新增 `MonitorEventGuard` 服务，负责：

1. 将 10 位秒或 13 位毫秒时间戳规范化为秒。
2. 要求请求时间与服务器时间相差不超过 300 秒。
3. 使用 `monitor_event:<sha256>` 作为内部唯一键，通过参数化 `INSERT IGNORE` 原子认领事件；重复键直接返回重复请求。
4. 保存 24 小时并在请求中清理过期内部键。

REST `monitor/heart`、`monitor/push` 与旧版 `appHeart`、`appPush` 共用该校验。推送匹配订单后使用 `UPDATE ... WHERE state=0`，只有实际影响一行时才发送通知，避免并发请求重复完成同一订单。现有 KSU 客户端无需升级即可使用。

### 4. 管理员初始化与密码存储

`vmq.sql` 不再提供 `admin/admin`。首次启动从 `ADMIN_USERNAME`、`ADMIN_PASSWORD` 环境变量初始化空的管理员记录；Docker Compose 将这两个变量设为必填，直接部署文档在 `.env` 中提供同名配置。密码使用 `password_hash()` 保存，登录使用 `password_verify()`；旧的明文记录仅在成功登录时兼容一次并立即升级为哈希。配置接口不再返回密码哈希，修改密码时只接受非空新密码。

登录成功后重新生成 Session ID，并启用 HttpOnly、SameSite 配置；旧登录页的环境检测弹窗、自动更新确认弹窗和仅跳转不注销的退出链接一并修正。

### 5. 示例、APK 和容器发布面

- 删除公开 Web 根目录中的测试下单表单和签单脚本；保留只验证回调签名的示例与 API 文档代码片段。
- 删除 `public/v.apk` 和旧 APK 下载按钮，后台配置页改为 KSU 模块链接，并明确 KSU 与旧 APK 不能同时运行。
- 将 `hulisang/vmqfox-frontend:latest` 固定为已核验的多架构 manifest digest `sha256:4ae8fdea55298c45bff5ffca70943ce03224b702a29e1b8bc051939df6f8a841`。
- 统一文档中的示例域名、签名值和许可证说明，移除真实二维码内容与固定生产密钥。

### 6. 数据库、出站请求和部署一致性

新安装 SQL 使用 InnoDB/utf8mb4；应用回调启用 TLS 证书和主机名校验。CORS 预检在调用控制器前直接返回。应用时区读取 `APP_TIMEZONE`/`TZ`，部署文档补充创建最小权限数据库用户、`.env` 权限和 PHP-FPM 依赖说明。

## 错误处理与兼容性

- 时间戳缺失、格式错误、超出窗口、签名错误和重复事件分别返回明确的 JSON 错误，不改变成功响应字段。
- 重放记录写入失败时拒绝处理支付事件并记录服务端错误，不能降级为无保护模式。
- 旧客户端继续使用 MD5 拼接协议；本次不强制增加客户端字段。KSU 的 13 位毫秒时间戳和旧 APK 的秒时间戳均可接受。
- 公开 API 文档同步说明时间窗口、已支付状态和示例密钥只用于演示。

## 验证策略

- PHP 单元测试覆盖时间戳秒/毫秒规范化、过期/未来请求、指纹生成、未支付返回地址拒绝和订单原子更新分支。
- 路由测试通过 ThinkPHP 实际路由解析验证：未声明 action 返回 404，敏感路由无认证返回 401，兼容路径仍可解析。
- 监控回归测试分别发送相同 REST 和旧版推送两次，确认第一次只完成一次订单，第二次被拒绝。
- 配置测试确认默认 SQL 无 `admin/admin`、密码不会出现在响应中，Compose 配置要求管理员环境变量并固定镜像 digest。
- 运行既有 PHP、Node、Python、Composer、Shell 和 Compose 验证；Docker daemon 可用时再执行实际镜像构建。

## 发布顺序

1. 先落地路由、认证、返回地址和监控保护，并运行回归测试。
2. 再完成管理员初始化、示例/APK 清理、Compose digest 和部署文档。
3. 暂存后执行秘密、大文件、二维码匿名化和许可证扫描。
4. 请求最终代码复审，修复 Critical/Important 项后提交并创建公开 GitHub 仓库。
